# 岗位精准定制 (JD-Based Customization)

## 步骤

### 1. JD 解析
从目标 JD 抽取四类要素：
- **必备技能**：岗位硬性要求（语言、框架、中间件）。
- **加分技能**：nice-to-have（特定平台、方法论）。
- **核心职责**：日常工作的关键词与动作。
- **高频关键词**：工具名、框架名、方法论（如 RAG、MCP、可观测、稳定性治理）。

### 2. 差距矩阵
构建矩阵，行 = JD 要求，列 = 简历现状 + 融入建议：

| JD 要求 | 简历现状 | 融入建议 |
|---|---|---|
| Kafka 消息队列 | ✅ 已覆盖 | 保留并前置 |
| 可观测体系 | ⚠️ 部分 | 在腾讯经历补「四路观测」关键词 |
| 稳定性治理 | ❌ 缺失 | 百度熔断/分流经验可迁移，补充表述 |

现状标记：✅ 覆盖 / ⚠️ 部分 / ❌ 缺失。

### 3. 关键词自然融入
- 仅在**真实经历**基础上加词，不虚构。
- 同义替换避免堆砌（如「监控」→「可观测体系」）。
- 把高价值关键词放在每条 bullet 的靠前位置，便于 6 秒筛选与 ATS 检索。

### 4. 匹配度量化
- 覆盖率 = 命中关键词数 / JD 关键词总数。
- 目标 ≥ 85%。
- 用 `scripts/ats_match.py --resume resume.md --jd jd.txt` 输出覆盖率与缺失项。
- 报告呈现前后对比，如 **62% → 89%**。

## 定制报告必须包含

1. JD 解析表（必备 / 加分 / 职责 / 关键词）。
2. 差距矩阵（✅/⚠️/❌ + 建议）。
3. 定制后简历全文。
4. 关键词前后覆盖率对比。

## 求职信要点（附赠）
- 首段点明目标岗位 + 最强匹配点。
- 中段用 1–2 个量化成果呼应 JD 职责。
- 末段表明意向与可到岗时间。

## 面试准备提示
- 针对 ⚠️/❌ 项准备「可迁移经验」话术。
- 把 Top 量化成果练成 30 秒电梯陈述。
